# Security reporting

Do not post credentials, exploit details, or private cluster information in public
issues. Report sensitive findings through the repository's GitHub **Security →
Report a vulnerability** feature when available. If private reporting is unavailable,
open an issue requesting a private reporting channel without disclosing the finding.

Do not run untrusted experiment configurations or submission scripts with privileged
accounts. Review setup commands and cluster profiles before submitting work.

Security fixes are maintained on the main development branch; there is currently
no separately supported release series.
